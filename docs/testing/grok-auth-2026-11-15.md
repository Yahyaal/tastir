# REPAIR.1 — signed-out Studio retries

The fresh live Studio sign-in page did not reproduce Grok’s long-session report. Source inspection found a separate concrete path: `StudioWork` loads projects and mounts `useStudioEvents` without the Studio page’s sign-in guard. The old poller retries every error, including a 401. A controlled 12-second regression generated 13 failed protected requests and failed the new “one request” assertion before the repair.

The shared session gate now checks `/api/me` once for simultaneous callers, remembers a confirmed sign-out in memory across route changes/remounts, and prevents protected requests until sign-in is explicitly verified. A login redirect starts a fresh document and verifies its cookie; the sign-in page also offers an explicit Check sign-in action. Ordinary polling, pulse and live-room requests all use the same gate. A 401 returns Studio to sign-in, stops background work and removes cached cloud project cards from Your work. This does not hide local work.

HTTP/network failures do not count as sign-out. A failed initial check shows an explicit retry without loading protected resources. Transient failures in an already signed-in poll back off, up to 30 seconds. Visibility changes do not create overlapping polls; unmount cancels polling. Session generations prevent late responses from reopening a newer signed-out session or publishing stale protected data.
