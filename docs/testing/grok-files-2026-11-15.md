# REPAIR.2 — editable downloads from the viewer

The editor already exported JSON. The repair exposes a clearly labelled pattern file in the viewer’s Take it with you section beside SVG/PNG, with a short explanation of editable files versus images. Downloading does not create a pattern or saved design in the browser.

The version-2 `.tastir.json` file embeds the complete construction and current design: selected ink IDs, palette/custom paints, wall style, grout, and optional Jali/pen appearance. Source information is preserved when known. Existing version-1 unfinished editor files and plain tutorial JSON keep their editor-opening behavior. Version 2 is explicit so old app versions reject it rather than silently losing appearance metadata. Files cannot be exported above the existing 8 MB import limit.

Opening a viewer file validates its drawing and appearance, creates a local editable pattern and saved design, then opens that design through the existing own-pattern route. The construction is embedded, not a library-only reference. A refused design write rolls back only the newly imported pattern; if even rollback is refused, the message explains the partial result. The uploaded file and existing work are never overwritten.

Twenty-two focused file/export tests passed, including all five styles, invalid/incomplete metadata, version compatibility, actual import records and a storage-quota rollback retaining prior work. Four production-browser cases passed across desktop/phone: real downloads and clean-browser imports for Lines and Jali, palette persistence, double pen/wash/ink and metal finish, plus reload. The export itself leaves the pattern store empty. Root lint/typecheck, all 13 root test tasks, production build and 24 file/sharing browser cases passed. The older unsupported-version assertion now uses a future version (999), retaining its original safeguard while version 2 is supported.
