## What documentation establishes

Vercel supports a root `api/index.ts` Node function, including Express. Root package `type: module` selects ESM. Its TypeScript support does **not** build TypeScript project references, so root `tsconfig` references cannot stand in for packaging workspace code. Use the Node runtime for the native renderer. [Node runtime](https://vercel.com/docs/functions/runtimes/node-js), [Express support](https://vercel.com/docs/frameworks/backend/express).

A root project gives the build access to all pnpm workspace packages. Workspace dependencies must be explicitly declared; Studio currently declares engine/schema/protocol and H4 must declare the live-room package it imports. Lockfile detection exists, but Vercel says an explicit `pnpm install` override selects the oldest available pnpm. H4's observed `installCommand` is `pnpm install --frozen-lockfile`, so **pin and verify pnpm 10.30.3 before the first deploy**. An allowed `vercel.json` fix is an explicit versioned install command such as `npx --yes pnpm@10.30.3 install --frozen-lockfile`; validate it in the actual build. [Monorepos](https://vercel.com/docs/monorepos), [package manager selection](https://vercel.com/docs/package-managers).

`outputDirectory`, `regions`, `functions.includeFiles` and rewrites are supported configuration fields. H4's observed config sets `dist/studio-hosted`, `cle1`, 60-second function duration and includes tutorials/fonts. It rewrites REST, MCP, OAuth discovery and sign-in/connection routes to `/api`. That is plausible configuration, **not a platform routing proof**. [Configuration reference](https://vercel.com/docs/project-configuration/vercel-json).

Vercel uses Node File Trace to collect function dependencies; computed filesystem reads may need `includeFiles`. Resvg ships precompiled native `.node` files, including Linux GNU builds. Thus a local PNG test proves the local binary works, not that Vercel's artifact contains it. [Vercel file tracing](https://vercel.com/kb/guide/how-can-i-use-files-in-serverless-functions), [resvg's own documentation](https://github.com/thx/resvg-js).

## Before the first deployed build — agent checks

1. **Use the merged tree and pin the install.** Repository root, Other framework, Node 22, production branch main; keep the lockfile and pnpm workspace intact. Verify `pnpm --version` in the build log is 10.30.3. Do not omit optional dependencies: resvg selects its native platform package from them. The H4 build command observed was only `VITE_TASTIR_STUDIO=hosted pnpm exec vite build --config apps/player/vite.config.mts --outDir ../../dist/studio-hosted --emptyOutDir`.

2. **Build with the actual Vercel builder.** After the owner creates the project, use `pnpm dlx vercel@64.5.0 login`, `pnpm dlx vercel@64.5.0 link` (select the existing project), `pnpm dlx vercel@64.5.0 pull --yes --environment=production`, then `pnpm dlx vercel@64.5.0 build --prod`. `.vercel/` is ignored and contains private pulled settings; do not attach it or its env files to reports. Vercel documents pulling project settings before a local build. [Build CLI](https://vercel.com/docs/cli/build), [pull CLI](https://vercel.com/docs/cli/pull).

3. **Prove workspace resolution.** Inspect `.vercel/output/functions/` and its function manifest. Import/run the **packaged function using only its packaged files**. It must not load source/dependencies from the development checkout. The packages export `@tastir/source` to `src/*.ts` but their default export points at `dist/*.js`; current TypeScript builds emit declarations only. `customConditions` in tsconfig helps TypeScript resolution and is not proof that Node File Trace or runtime resolution uses that condition. The frontend's Vite build alone does not supply server JavaScript.

   If the standard builder cannot package these imports, fix **only the API entry and build command/config**: prebundle the server to a generated JavaScript module with the bundler condition `@tastir/source`, bundle the internal `@tastir/*` code, and have `api/index.ts` import that generated module. Keep Node built-ins and native resvg external. An indiscriminate `packages: external` would also externalize the unbuilt workspace packages, so it does not solve this. Avoid adding `NODE_OPTIONS=--conditions=@tastir/source` as the only fix: it does not guarantee packaged TypeScript is compiled. Preserve filesystem paths used for tutorials/fonts when bundling. This fix is conditional on the artifact test, not claimed implemented here.

4. **Prove native/assets packaging.** Locate the resvg JavaScript loader and matching Linux/architecture `.node` binary in the function artifact, including pnpm's actual resolved dependency path. Run a real PNG conversion from the isolated artifact; include a tutorial load and the bundled font used by `picture.ts`. If tracing misses assets/native files, narrow explicit `functions["api/index.ts"].includeFiles` globs to their real build paths, then rebuild. Do not copy the whole workspace/node_modules into the function. Confirm compressed/uncompressed artifact sizes against Vercel's current limits. Production Vercel must also return an actual PNG; an SVG-only success is insufficient.

5. **Prove rewrites and request bodies on Vercel.** Fetch `/` and a built static asset. Anonymous `/api/me` must return JSON 401, not a static 404 or HTML. OAuth discovery at `/.well-known/oauth-authorization-server` must name the production site; anonymous `/mcp` must return an OAuth 401 with the expected resource metadata. `/login` must produce a Google redirect with callback `https://<site>/auth/google`; callback, token, register, revoke, consent and connection routes must reach Express at their original paths. Exercise a JSON save and a consent form POST: confirm the platform does not pre-consume the body before Express parses it. If necessary, an API/config fix is Vercel's documented `NODEJS_HELPERS=0` setting, followed by testing both body types. [Advanced Node configuration](https://vercel.com/docs/functions/runtimes/node-js/advanced-node-configuration).

6. **Check real persistence/private access.** Use the owner's Google session to save/reload/redeploy/export, upload and read a private Blob photo, and get a rendered PNG. ## Database URL compatibility

Reading the pinned postgres.js 3.4.9 sources (`src/connection.js` and `src/index.js` in its installed package) shows that `sslmode=require` explicitly disables certificate verification, whereas `verify-full` keeps Node's certificate verification. Unknown URL parameters are forwarded as server startup settings; this driver has no `channel_binding` implementation. The guide/preflight therefore require `sslmode=verify-full` and reject a libpq `channel_binding` parameter. This changes deployment configuration, not Studio source. The preflight connection also explicitly requires certificate verification. Tests check the real driver's parsed SSL option; successful Neon connectivity still needs the owner's actual database.
