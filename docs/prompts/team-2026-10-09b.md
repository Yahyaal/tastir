**The problem.** When a learner presses Ink in draw along (`apps/player/src/along/inkWork.ts`, `prepareInk`), the app waits about 5 seconds on Bou Inania before the pen works. Measured on 9 October, on one core:

| Tutorial | `inkPieces(scene, cell, { allEdges: true })` | bits | `computePattern(scene, t, strokesOf(pieces, classic))` | `computePattern(scene, t)` |
| --- | ---: | ---: | ---: | ---: |
| bou-inania-rosette | 1,848 ms | 177,343 | 3,061 ms | 697 ms |
| bou-inania-twelve-fold-wall | 2,401 ms | 190,945 | 2,274 ms | 264 ms |
| kurt-eight-fold-zellige | 728 ms | 6,767 | 665 ms | 315 ms |
| alhambra-reyes-stars | 203 ms | 8,603 | 248 ms | 77 ms |
| eight-fold-star-and-cross | 8 ms | 60 | 9 ms | 6 ms |

`constructionCrossings` (only tests use it) is also very slow: 46 s on bou-inania-rosette and 31 s on the wall, 0.6 s on Kurt.

**The goal.** Do these in order, one commit each:

1. Add `tools/bench-engine.mts`, which times the calls above for every tutorial in `tutorials/` and prints a table like the one above. Commit it first with the numbers it prints on `main`.
2. Make `inkPieces` with `allEdges` and `computePattern` from strokes each take **under 300 ms on both Bou Inania tutorials**, without slowing any other tutorial. Profile first (`node --cpu-prof`) and put what you found in the commit message. Likely places to look are pairwise loops over every curve and every bit, point merging that compares every point with every other, and string keys built in hot loops; prefer a spatial index or sorting over a pairwise scan.
3. Make `constructionCrossings` take under 1 s on both Bou Inania tutorials.

**What must not change.** The results must be **identical**, not just close. Keep the old version in the spec file as the reference. No tutorial file and no `expect` block may change, and every golden test must pass untouched. If an output does change, stop and explain which tutorial and why rather than adjust the test. Keep the engine free of DOM, Node and runtime dependencies (`pnpm typecheck` fails otherwise).
